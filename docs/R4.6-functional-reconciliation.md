L’écrasement général d’archives signalé **n’a pas été reproduit**. L’identifiant de session est distinct de la graine. Sur Web, le verrou inter-onglets accompagne une écriture atomique dans le stockage local. Sur Android, les instances partagent une file d’écriture qui remplace la session et ses archives ensemble. La comparaison avec la dernière valeur lue protège contre un rédacteur périmé. Les tests couvrent une écriture interrompue, un accusé d’écriture perdu et la suppression individuelle suivie d’une reprise.

Les sauvegardes existantes gardent leur clé publique et leur contrat. Les archives anciennes n’indiquent pas si leur graine a été choisie par un joueur ou par un développeur. Leur provenance historique ne peut donc pas être certifiée. Les nouveaux playtests sont isolés, même après redémarrage. Le jeu hors ligne reste modifiable par le propriétaire du client. Il n’existe pas de classement Rogue mondial.

## Gameplay Rogue vérifié

Les nouvelles sessions utilisent `rogue-v1-r4.2-1`. Les fixtures du contrat précédent restaurent six états et les trois rencontres suivantes. Les chiffres 3, 5, 7, les opérations addition, soustraction, multiplication, leurs priorités et l’absence de parenthèses sont vérifiés dans le moteur partagé. Trois vies, trois indices, trois rencontres ordinaires par acte, puis Le Gardien (2 phases), Le Maître (2) et L’Architecte (3) donnent 16 réussites. La survie est ouverte après la victoire, sans plafond de rencontres dans le jeu.

Le test de 680 générations couvre les douze cartes, les quatre améliorations majeures et les combinaisons D1/D2/T3, sur les phases des boss et à plusieurs profondeurs de survie. Les tests séparés vérifient coûts, expiration par tentative ou réussite, cumul, bouclier, seuil de précision, offres admissibles et passage sans carte. Les gains, contreparties et durées de chaque carte sont détaillés dans la [revue des douze cartes](R4.2-rogue-difficulty.md). Aucune modification de coefficients dans R4.6.

Sur 1 800 runs, zéro refus de génération et zéro avertissement de coût heuristique. Chaque rencontre possède un témoin. Le minimum est établi dans une recherche bornée à six chiffres, magnitude 500, cible 150 et 350 000 états. L’heuristique de temps reste une estimation. Les agents connaissent les solutions. Une durée suffisante pour un joueur, la fatigue de saisie et la maîtrise perçue nécessitent des playtests humains.

D1 et T3 excluent un optimum dans les 2 037 expositions mesurées des actes officiels. D2 vérifie la pertinence du budget de multiplications. Les paires d’obligations peuvent rester partiellement redondantes. Les pools de survie descendent à deux cibles et le minimum moyen atteint le plafond de six chiffres. La mémoire courte peut relâcher une préférence de variété pour conserver les règles actives. Ce sont les limites prioritaires pour les prochains playtests.

Un second échantillon a utilisé trois stockages neufs en mémoire, dix créations publiques par stockage avec Web Crypto. Les deux premières rencontres ont été résolues pour comparer les offres sans tenir compte de leur ordre. Bilan de cette exécution : **30 graines, 28 premières cibles, 30 paires de cibles et 16 premiers tirages de cartes distincts**. Le test déterministe à graine identique et le test d’isolation complètent cette observation. Les tirages aléatoires peuvent se répéter. [Mesures](assets/R4.6/diversity.json)

## Classic et décision à prendre

La grille affiche les niveaux ouverts, les meilleures étoiles de chacun et les niveaux encore verrouillés. Le meilleur résultat remplace le précédent. Rejouer un niveau parfait conserve son total d’étoiles et son unique maîtrise. Les données historiques agrégées ne permettent pas de reconstruire les anciens doublons entre tous les modes.

Le seuil de 50 étoiles au niveau 20 trouvé dans les références Classic V2 était illustratif. Aucun seuil approuvé n’a été retrouvé. Pour un essai au niveau 20, comparer une condition de **40 meilleures étoiles sur les 57 disponibles** avec une condition combinée de **40 étoiles et 4 niveaux parfaits distincts**. Par exemple, 19 niveaux à deux étoiles en donnent 38. Porter quatre de ces résultats à trois étoiles donne 42 et quatre maîtrises. Examiner le nombre de replays requis des joueurs avant de choisir seuil, emplacement et critères. Aucun de ces paliers n’est activé.

## Builds, preuves et essai physique

Les contrôles ont été exécutés depuis la racine, sauf Gradle depuis `apps/mobile/android`.

```sh
npm test
npm run typecheck -w @shortest/engine
npm run typecheck -w @shortest/web
npm run typecheck -w @shortest/mobile
npm run build -w @shortest/web
npm run compare:rogue-difficulty -w @shortest/engine -- --runs 300 --seed 42 --survival 4 --out /tmp/r46-comparison.json
NODE_ENV=production ./gradlew --offline :app:assembleRelease -PreactNativeArchitectures=x86_64,arm64-v8a
git diff --check
```

Le build Web et les typechecks couvrent également les tests Web, les outils de playtest et les types Supabase. Android a produit un APK release habituel et un APK release de playtest signé avec la clé de test du projet. Le second diffère par son identifiant `com.shortest.r46playtest`, substitué à la configuration Gradle pour cohabiter avec l’installation existante. Une première compilation avait échoué lors de deux générations concurrentes des mêmes assets. Les compilations de livraison ont été effectuées successivement.

L’APK destiné au propriétaire est le fichier local `apps/mobile/android/app/build/outputs/playtest/MathPrime-R4.6.apk`. Il contient les architectures ARM64 et x86_64 et requiert Android 7.0/API 24 ou supérieur. L’environnement de test matériel reste à valider.

1. Installer l’APK sur le téléphone avec `adb install -r MathPrime-R4.6.apk`. Identifier l’application de test par son paquet si l’ancienne application est présente.
2. Ouvrir Rogue. Vérifier l’absence de sélecteur de graine. Démarrer une rencontre, noter la cible, les vies et le temps, puis prendre un indice.
3. Passer à l’accueil Android, attendre environ dix secondes, puis revenir. Forcer ensuite l’arrêt du paquet de test et relancer. Comparer cible, ressources, temps écoulé et saisie avec les valeurs relevées.
4. Terminer une campagne, utiliser des cartes, poursuivre en survie et y perdre la dernière vie. Vérifier les trois boss et la victoire dans le bilan.
5. Ajouter un abandon et une défaite, fermer et relancer, remplacer une partie inachevée puis supprimer uniquement cette quatrième archive. Vérifier les trois résumés initiaux.
6. En Classic, atteindre trois niveaux avec des scores d’une, deux et trois étoiles. Vérifier que le quatrième s’ouvre et qu’un rejeu parfait n’ajoute aucune maîtrise. Relever aussi la lisibilité, le maniement et la difficulté ressentie sur ce téléphone.

Le contrôle spécifique de sélection a été rejoué sur le Web et dans l’APK livré. Après sélection du premier chiffre de `3+`, effacement complet et nouvelle saisie de `3+`, le pavé garde ses opérateurs actifs. Sur Android, la mise à jour de l’APK par-dessus l’installation de playtest a aussi conservé les trois archives de la campagne précédente.
